# Отчёт: отработка гостей «Конференции 2026» командой NewBiz

Отчёт сам обновляется из amoCRM каждый день в 06:17 МСК, а также по кнопке.

- **[REPORT.md](REPORT.md)**: сводка, таблицы и список сделок.
- **`docs/index.html`**: интерактивная страница с фильтрами по сегменту гостей и сотруднику, поиском и сортировкой сделок.

## Как устроено

```
amoCRM API ──► scripts/fetch_amo.py ──► data/snapshot.json ──► scripts/build_report.py ──► REPORT.md + docs/index.html
```

GitHub Actions (`.github/workflows/update-report.yml`) запускает обе команды и коммитит результат, если цифры изменились. Выгрузка `data/` в репозиторий не попадает.

Настройки (id воронок и полей, дата конференции, исключения) лежат в `scripts/config.py`.

## Подключение (один раз)

1. **Токен amoCRM.** Зайти в amoCRM под администратором: *Настройки → Интеграции → Создать интеграцию → Внешняя*. В доступах оставить все галочки и сохранить. Затем на вкладке *Ключи и доступы* нажать *Сгенерировать долгосрочный токен*. Срок можно поставить максимальный. Токен работает с правами создавшего его пользователя, поэтому нужен админ: он видит все сделки и события.
2. **Секрет в GitHub.** В репозитории открыть *Settings → Secrets and variables → Actions → New repository secret*, указать имя `AMO_TOKEN` и вставить токен.
3. **Первый запуск.** Открыть *Actions → «Обновить отчёт из amoCRM» → Run workflow*. Примерно через 2–3 минуты обновятся REPORT.md и docs/index.html.
4. **Интерактивная страница.** Её можно скачать из запуска Actions: артефакт `report-html`. Либо включить GitHub Pages: *Settings → Pages → Deploy from a branch → main / docs*.

⚠️ Если репозиторий публичный, страница Pages и REPORT.md видны всем. В них названия клиентов и бюджеты. Лучше сделать репозиторий приватным: *Settings → General → Danger zone → Change visibility*. Учтите, что Pages для приватных репозиториев доступен только на платных тарифах GitHub. На бесплатном тарифе можно скачивать артефакт или смотреть REPORT.md.

## Локальный запуск

```bash
export AMO_TOKEN=...            # долгосрочный токен
python3 scripts/fetch_amo.py
python3 scripts/build_report.py
open docs/index.html
```

## Методика

- **Сегмент гостя** определяется по полям сделки: «Сотрудник», «Участвовал офлайн», «Участвовал онлайн», иначе «не участвовал». Рабочий список NewBiz — это офлайн-гости.
- **Отработка гостя:**
  - «Новый лид» (поле включено);
  - «Действующий лид» (такая причина отказа);
  - другая причина: если её поставил сотрудник — это «отказ вручную», если она проставлена с учётки из `AUTO_USERS` — «закрыт массово»;
  - иначе — «не разобран».
- **Кто поставил отметку** определяется по последнему событию изменения поля в amoCRM.
- **Связь с NewBiz.** Сделка NewBiz считается пришедшей от гостя, если она создана после конференции и у неё тот же контакт, что у гостя. Для гостей с «Новый лид» достаточно совпадения компании.
- **Исключения.** Компании из `EXCLUDE_NB_COMPANY_IDS` (действующие клиенты) показываются в списке, но в конверсию не входят.
